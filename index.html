01 Endereçamento IP com Classe e Sem Classe (CIDR) Introdução · Classes · CIDR · /0 a /32 · Regras de uso

1.1 O que é endereçamento com classe e sem classe?

O endereçamento IP com classe e sem classe são duas arquiteturas que definem como os endereços de rede são organizados e alocados. A principal diferença entre elas está na rigidez das regras de divisão entre a parte que identifica a rede e a parte que identifica os dispositivos (hosts).

1.2 Endereçamento IP com Classe (Classful)

Este foi o sistema original da internet, definido na década de 1980. Sua principal característica é a divisão do espaço de endereços em classes fixas (A, B, C, D e E), onde a própria máscara de sub-rede é implicitamente determinada pelo primeiro octeto do endereço IP.

Detalhes por classe

  • Classe A: projetada para redes muito grandes. O primeiro octeto (8 bits) identifica a rede e os três octetos restantes (24 bits) identificam os hosts. Máscara padrão 255.0.0.0 (/8). Faixa: 1.0.0.0 a 127.255.255.255. Aproximadamente 16,7 milhões de endereços por rede.
  • Classe B: destinada a redes de médio porte. Os dois primeiros octetos (16 bits) identificam a rede e os dois últimos (16 bits) identificam os hosts. Máscara padrão 255.255.0.0 (/16). Faixa: 128.0.0.0 a 191.255.255.255. 65.536 endereços por rede.
  • Classe C: usada para redes menores. Os três primeiros octetos (24 bits) identificam a rede e o último octeto (8 bits) identifica os hosts. Máscara padrão 255.255.255.0 (/24). Faixa: 192.0.0.0 a 223.255.255.255. 256 endereços por rede.
  • Classe D: reservada para Multicast (transmissão para grupos de dispositivos). Não é usada para endereçar hosts individuais. Faixa: 224.0.0.0 a 239.255.255.255.
  • Classe E: reservada para uso futuro e experimentos. Não é usada para endereçamento normal na internet. Faixa: 240.0.0.0 a 255.255.255.255.

Principais limitações: esse modelo se mostrou ineficiente e rígido. Uma organização que precisasse de 300 endereços, por exemplo, receberia um bloco de Classe C (256 endereços), que é insuficiente, ou um bloco de Classe B (65.536 endereços), que é um enorme desperdício. Esse descompasso contribuiu significativamente para o esgotamento dos endereços IPv4.

1.3 Endereçamento IP sem Classe (Classless / CIDR)

Para resolver as limitações do modelo com classes, foi introduzido em 1993 o CIDR (Classless Inter-Domain Routing), que é a base do endereçamento sem classe. A ideia central é ignorar as classes fixas e permitir que o bloco de endereços seja alocado em qualquer limite de bits, de acordo com a necessidade real de cada organização.

Principais características

  • Alocação flexível (blocos de tamanho variável): uma organização que precisa de 2.000 endereços pode receber um bloco de 2.048 endereços (uma potência de 2), sem desperdício. O tamanho do bloco é definido por um prefixo de rede que pode ter qualquer comprimento.
  • Máscara de sub-rede explícita: no modelo sem classe, a máscara não é mais implícita. Ela precisa ser especificada junto com o endereço IP para indicar exatamente quantos bits identificam a rede e quantos identificam os hosts.
  • Notação CIDR: uma forma compacta de representar a máscara. Em vez de escrever 255.255.255.0, usa-se a notação /24 após o endereço IP (ex.: 192.168.1.0/24). O número indica a quantidade de bits "1" no prefixo da rede.
  • VLSM (Variable Length Subnet Mask): técnica que permite usar máscaras de sub-rede de tamanhos diferentes dentro da mesma rede principal. Isso possibilita uma hierarquia de sub-redes, otimizando ainda mais o uso do espaço de endereçamento.

1.5 CIDR: de quanto até quanto?

No IPv4, o prefixo CIDR é um número que pode variar de 0 a 32. Ele indica quantos bits do endereço IP são fixos para identificar a rede. O valor após a barra (/) representa essa quantidade de bits.

Prefixo mínimo /0

Representa toda a Internet (nenhum bit fixo para rede, todos os 32 bits variáveis).

Prefixo máximo /32

Representa um único endereço IP (todos os 32 bits fixos, ou seja, um host específico).

1.6 Como ele varia? A relação é inversa

A variação do prefixo segue uma lógica simples: quanto menor o número após a barra, maior o bloco de endereços; quanto maior o número, menor o bloco.

Isso acontece porque o prefixo define quantos bits são "congelados" para a rede. Os bits restantes ficam livres para variar e endereçar os hosts. A quantidade de endereços em um bloco é calculada por 2^(32 − prefixo).

1.7 Posso usar qualquer um? Sim, tecnicamente — com ressalvas práticas

Tecnicamente, qualquer prefixo de /0 a /32 é válido na notação CIDR. Você pode usá-los para projetar sua rede interna como desejar.

Na prática, porém, o uso de endereços IP públicos (roteáveis na Internet) é rigidamente controlado por organizações como LACNIC, ARIN, etc. (os Registros Regionais de Internet). Elas estabelecem políticas de alocação para evitar o desperdício e garantir a eficiência do espaço IPv4. Por exemplo:

  • Há tamanhos mínimos de alocação para provedores e organizações (por exemplo, um bloco /20 em algumas regiões).
  • As organizações precisam comprovar a necessidade real e a utilização eficiente dos blocos já recebidos para solicitar mais endereços.

Portanto, você não pode simplesmente "reservar" um bloco público de seu interesse na Internet. Para redes privadas, você tem total liberdade para usar os prefixos que fizerem sentido para o seu projeto:

Dentro das faixas privadas, você pode subdividir livremente com qualquer prefixo — inclusive usando VLSM.

1.8 Todo endereço já vem com o CIDR indicado?

Não necessariamente. A notação CIDR (/n) é obrigatória quando se deseja representar um bloco de rede (um conjunto de endereços). Um endereço IP isolado (ex.: 192.168.1.10) identifica apenas um host, e não contém, por si só, a informação de qual é a sua rede.

  • Em contextos técnicos (configuração de roteadores, APIs, documentação), a notação CIDR é exigida para especificar redes. Por exemplo, a especificação OpenAPI define que um valor no formato ipv4-cidr deve ser um endereço seguido de uma barra e um número de 0 a 32; um endereço "simples" sem o prefixo não é aceito nesse formato.
  • Informalmente, ao se referir a um host específico, pode-se usar apenas o endereço IP. Nesse caso, subentende-se um prefixo /32 (que representa aquele host individual).

Resumindo: para definir uma rede, o CIDR é a forma padrão e necessária de se expressar. Para apenas identificar um dispositivo, o endereço IP sozinho pode ser suficiente em conversas casuais, mas a notação completa é sempre a mais precisa.

1.9 Conclusão do módulo 1

Em resumo, o endereçamento sem classe (CIDR) foi a solução que permitiu um uso muito mais eficiente do espaço de endereços IPv4, prolongando sua vida útil e tornando-se o método padrão utilizado hoje. O modelo com classes cumpriu seu papel histórico, mas sua rigidez inviabilizou a escala da Internet moderna.

02 Subnetting — Guia Organizado TEC INFO VTR · Fórmulas · VLSM · Armadilhas

2.1 Introdução ao Subnetting

  • Subnetting é dividir uma rede grande em sub-redes menores e organizadas.
  • Não é "decoreba": é matemática aplicada.
  • Serve para o roteador saber para qual máquina enviar cada pacote.
  • Ajuda a organizar setores como TI, RH e Financeiro.
  • Benefícios:
    • Mais segurança.
    • Gerenciamento mais fácil.
    • Menos tráfego desnecessário.

2.2 Analogia do endereço IP

  • Um IPv4 funciona como o endereço de uma casa:
    • Rua + número do prédio = parte da rede.
    • Número do apartamento = host.
  • Todo IPv4 se divide em:
    • Parte que identifica a rede.
    • Parte que identifica o host.

2.3 Estrutura do IPv4 e troca entre rede e host

  • Todo endereço IPv4 tem 32 bits.
  • Criar sub-redes é fazer uma troca:
    • Emprestar bits do host para a rede.
  • Consequências:
    • Mais bits para rede = mais sub-redes.
    • Menos bits para host = menos máquinas por sub-rede.

2.4 Fórmula dos hosts utilizáveis

  • Fórmula: 2n − 2
    • n = quantidade de bits restantes para hosts.
  • Exemplo:
    • 8 bits para host: 2⁸ = 256; 256 − 2 = 254 hosts utilizáveis.
  • Por que subtrair 2?
    • O primeiro endereço do bloco é o ID da rede.
    • O último endereço do bloco é o broadcast.
    • Nenhum dos dois pode ser usado em uma máquina.

2.5 Atalho do tamanho do bloco

  • Fórmula do bloco: 256 − valor da máscara no octeto dividido.
  • Exemplo:
    • /26 termina em 192.
    • 256 − 192 = 64.
    • O bloco "pula" de 64 em 64.
    • Redes: .0, .64, .128, .192.
  • Padrão observado:
    • A cada bit roubado para a rede, o número de sub-redes dobra.
    • A quantidade de hosts cai pela metade.

2.7 Método dos 4 passos

  1. Qual é a máscara?
    • Exemplo: /27 termina em 224.
  2. Calcular o bloco:
    • 256 − 224 = 32.
  3. Listar a "escada" das redes:
    • Pular de 32 em 32.
  4. Ver em qual degrau o IP cai:
    • Início do degrau = rede.
    • Fim antes do próximo degrau = broadcast.

2.8 Exemplo prático com IP

  • IP recebido: 192.168.10.77/27.
  • Máscara /27 = 224.
  • Bloco = 256 − 224 = 32.
  • Escada de redes: 0, 32, 64, 96...
  • O IP 77 está entre .64 e .95.
  • Resultado:
    • Rede: 192.168.10.64.
    • Broadcast: 192.168.10.95.

2.9 Exemplo prático em empresa

  • Rede recebida: 192.168.1.0/24.
  • Necessidade: 4 departamentos com cerca de 50 PCs cada.
  • Usando /25:
    • Cria apenas 2 redes.
    • Não atende bem.
  • Usando /26:
    • Cria 4 redes de 62 hosts.
    • Solução adequada.
  • Distribuição:
    • TI: 192.168.1.0.
    • RH: 192.168.1.64.
    • Financeiro: 192.168.1.128.
    • Diretoria: 192.168.1.192.

2.10 VLSM — Máscaras de Comprimento Variável

  • VLSM permite usar máscaras diferentes conforme a necessidade.
  • Evita desperdício de IPs.
  • Exemplo:
    • Engenharia precisa de 100 máquinas.
    • Diretoria precisa de apenas 10.
  • Estratégia correta:
    • Atender primeiro as maiores demandas.
    • Depois as menores.
  • No exemplo:
    • Engenharia: bloco /25.
    • Diretoria: bloco /28.

2.11 Armadilhas clássicas para iniciantes

  1. Usar o ID de rede em uma máquina
    • Exemplo: usar .0 em um host — jamais.
  2. Fazer ping no broadcast como se fosse host
    • O último endereço do bloco também é intocável.
  3. Achar que /26 significa 26 hosts
    • Erro fatal.
    • /26 significa 26 bits reservados para a rede.
  4. Achar que prefixo maior é rede maior
    • É o contrário.
    • Quanto maior o prefixo, como /28, menor a quantidade de hosts.

Atenção: essas quatro armadilhas derrubam a maioria dos iniciantes — revise-as antes de qualquer prova ou configuração real.

2.12 Resumo final

  • Mais bits para rede = mais sub-redes e menos hosts.
  • Fórmula dos hosts utilizáveis: 2n − 2.
  • Tamanho do bloco: 256 − máscara.
  • Não é necessário decorar tabelas gigantes.
  • Regra prática:
    • Início do degrau = rede.
    • Endereço anterior ao próximo degrau = broadcast.
  • O computador usa a máscara para saber:
    • Se o destino está na mesma rede.
    • Ou se precisa enviar o pacote ao roteador.

2.14 Anexo — Método do "Número Mágico"

O método mais rápido para calcular sub-redes usa o "Número Mágico" (base 256). Você descobre a máscara e os intervalos sem converter números para binário.

Exemplo prático: calcular a rede 192.168.10.0/26.

Passo 1 — Octeto interessante e bits emprestados

Um IPv4 tem 4 octetos de 8 bits cada (8, 16, 24 e 32).

  • Encontre a faixa: O /26 está entre 24 e 32, então o foco é o 4º octeto.
  • Os anteriores ficam cheios: A máscara começa com 255.255.255.X.
  • Bits que sobraram: 26 − 24 = 2 bits.

Passo 2 — Calcule o "Número Mágico"

  • Potência de 2: 8 − 2 = 6.
  • Calcule o salto: 2⁶ = 64.
  • Resultado: O número mágico é 64. As redes pulam de 64 em 64 no 4º octeto (0, 64, 128, 192).

Passo 3 — Encontre a Máscara de Sub-rede

  • Faça a conta: 256 − 64 = 192.
  • Máscara final: 255.255.255.192.

Passo 4 — Monte a faixa de IPs

  • Hosts: são todos os números entre o endereço de rede e o broadcast.

3.1 Introdução e Estrutura dos Endereços IPv4

  • Apresentação e contexto: O endereço IP situa dispositivos dentro da rede para identificação e compartilhamento de recursos.
  • Composição: O endereço IPv4 é composto por 4 octetos (32 bits no total), onde cada octeto representa um valor decimal entre 0 e 255 separado por pontos.
  • Base binária: Em sua essência, o IP é formado por sequências de zeros e uns (são 8 bits por octeto).
  • Divisão dos bits: Dos 232 endereços possíveis, cada IP é dividido em uma parte que identifica a rede e outra que identifica o host.
  • Histórico: A divisão por classes (A, B, C, D e E) foi utilizada para organizar o endereçamento até 1993.

3.4 Endereços Reservados, IPs Privados e NAT

  • Motivação: Devido ao esgotamento de endereços IPv4 públicos (impulsionando a transição para o IPv6), foram criadas faixas privadas para uso interno em redes locais.
  • Faixas de IP Privado (RFC 1918):
    ClasseBloco CIDRFaixa completa
    A10.0.0.0/810.0.0.0 – 10.255.255.255
    B172.16.0.0/12172.16.0.0 – 172.31.255.255
    C192.168.0.0/16192.168.0.0 – 192.168.255.255
  • Outros endereços especiais:
    • 0.0.0.0: Endereço especial reservado.
    • 169.254.0.0/16: Endereço Zeroconf / APIPA (configuração automática quando não há DHCP).
  • Papel do NAT (Network Address Translation): Permite que múltiplos dispositivos em uma rede local utilizem IPs privados internamente e compartilhem um único IP público válido para se comunicar com a Internet.

Em resumo: os IPs privados resolvem o uso interno; o NAT faz a "ponte" com a Internet usando um único IP público.
